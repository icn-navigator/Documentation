## Background
Sprint feedback highlighted the need to use **GitHub Projects more effectively** for task management. Proper use of labels, priorities, and assignments would improve visibility of progress and accountability.

## Relevant Data
- Currently, tasks and subtasks are sometimes tracked informally in meeting notes.  
- GitHub Projects supports priorities, labels, and automated views (Kanban).  
- Clearer tracking would align with agile practices and support sprint reviews.  

## Options Considered
**Option 1: Continue ad-hoc task tracking in Discord/meeting notes**  
- Pro: Minimal overhead.  
- Con: Poor visibility; hard to measure sprint progress.  

**Option 2: Use GitHub Projects without labels/priority fields**  
- Pro: Simple to maintain.  
- Con: Limited tracking; difficult to manage larger backlog.  

**Option 3: Use GitHub Projects with labels and priorities (Chosen)**  
- Pro: Better organisation, supports sprint rituals, clear ownership.  
- Con: Requires team discipline to keep board updated.  

## Action Items
- Define and apply labels (e.g., `frontend`, `backend`, `documentation`).  
- Use priority fields to rank tasks within each sprint.  
- Assign tasks to individual team members.  
- Link tasks to GitHub issues and meeting action items.  

## Outcome
The team decided to **actively use GitHub Projects with labels, priorities, and assignees**.  
This improves visibility, supports agile reviews, and strengthens accountability across the team.
