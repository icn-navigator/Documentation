## Background
During sprint feedback, the team was advised to include **use case diagrams** and a **domain model** as part of standard project artefacts. These diagrams improve clarity of system behaviour, help align development tasks with user stories, and serve as communication tools with the client.

## Relevant Data
- User stories (US01–US08) define functional requirements (e.g., map view, filtering, onboarding).  
- A domain model was needed to represent entities such as `User`, `Company`, `Capability`, and `Organisation`.  
- Use case diagrams provide a higher-level overview of interactions between users and the system.  

## Options Considered
**Option 1: Skip use case and domain models**  
- Pro: Saves time.  
- Con: Artefacts required for marking; weakens design clarity.  

**Option 2: Include basic diagrams with limited detail**  
- Pro: Quick to prepare; sufficient for review.  
- Con: May miss relationships and details important for developers.  

**Option 3: Include complete use case diagram + detailed domain model (Chosen)**  
- Pro: Clear representation of actors, system boundaries, and domain entities.  
- Con: Requires additional effort to maintain consistency with evolving stories.  

## Action Items
- Create use case diagram covering main user flows (signup, map view, filter, company profile).  
- Create domain diagram showing entities and relationships (`User`, `Company`, `Capability`, `Organisation`).  
- Add diagrams to documentation and link from README.  

## Outcome
The team decided to **include both use case and domain model diagrams** as standard project artefacts.  
These diagrams provide clarity for developers, support sprint reviews, and strengthen alignment with user stories.
